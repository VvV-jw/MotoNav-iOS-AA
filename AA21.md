# AA21 Map Sync

Version: `0.15.21-aa.21`, build `21`.

Selective upstream reference:
`zyn950929/MotoNav@e12251629ce3dc3808da34fcca0917c9c62bb5fc`
(iOS 0.16.2 Build16, published November 2, 2026).
The application remains based on local AA main `1d89c7c`.

## Included

- Navigation routes take priority over queued map fragments. Continuous position
  updates share the writer with maps, while control commands retain priority.
  Receiver-load pacing and bounded ATT retries remain enabled.
- Type 1 GTA5 and type 3 raster maps repeat only their final fragment when K
  might be lost. Timers begin after the real final transport completion:
  probes at 0.3 and 0.6 seconds, then same-ID full retry after 2 seconds for
  vectors or a 12-second processing grace for raster maps. No timer creates
  a successful map acknowledgement.
- Cache selection runs separately from screenshot jobs and their failure
  backoff. Nearby cached coverage can recover a usable map after movement.
  Route preparation follows the actual route with the existing dynamic
  preparation estimate and style-specific map bounds.
- Buildings yield to essential roads when the measured BLE rate and remaining
  coverage cannot accommodate them. Budgeting uses negotiated, encoded wire
  sizes, including legacy conversion and RZ1 compression.
- Vice City building continuity is explicitly selected with `#BC,1` or
  `#BC,0`. Firmware without this command retains its original behavior.
- The existing cruise/navigation exclusion and "end cruise first" alert are
  retained from the local build 19 work. Ending cruise requires an explicit
  action and does not automatically start navigation.

## Preserved

GTA5 vector tiles and 2400-meter half bounds, map palette behavior, RZ1
negotiation, cache LRU and active-route protection, freshness checks, resource
pauses and recovery, saved itineraries, ordered stops, SDK vehicle selection,
navigation sessions, and original signing/bundle identity are retained.

No experimental traffic-countdown binary hooks are included.

## Verification Boundary

The existing Mac workflow builds the actual unsigned iPhone application and
share extension, then executes all Swift regression suites. AA21 adds cases
for acknowledgement loss, packet identities, writer fairness, map handoff,
wire budgets, nearby coverage, and the production cruise intent guard.

The unsigned IPA must be signed before installation. Source and package
verification do not establish physical BLE reliability, lock-screen runtime,
ESP32 processing deadlines, panel FPS, or real-road behavior. This release
is packaged for later installation; no device write is part of preparation.
