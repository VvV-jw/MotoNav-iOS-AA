# iOS AA23 Media and Call Controls

Version: 0.15.23 (23). The app identifiers remain `com.example.motonav`
and `com.example.motonav.share`. Install over the existing native app with the
same signing account to retain its data.

The matching 1.75C AA15 media firmware adds physical media buttons and a small
yellow call waveform beside the battery. Short presses can be swapped in the
app's device settings to accommodate the physical mounting direction. The power
key's hardware long-press shutdown remains unchanged. No firmware update is
flashed automatically.

The app observes system-visible telephone and CallKit calls without reading a
phone number or recording audio. It sends only inactive, ringing, dialing,
active or held. The latest state is re-read before reconnect and refreshed every
ten seconds; the display clears an indicator on disconnection or after twenty
seconds without a state refresh. It does not infer calls from microphone use or
generic audio interruptions. A WeChat call that is not exposed through CallKit
cannot be reliably detected, and a call cannot be attributed to a specific app
using these flags.

Navigation speech now has an independent, persisted 0-100% gain. A zero gain
does not activate the audio session or duck music. During a system-visible call,
the app stops navigation speech and discards queued old instructions; after a
call it speaks only future instructions. Completion callbacks for cancelled
old utterances cannot release a newer speech session. The native system media
slider remains user-operated. Neither it nor the navigation gain gives MotoNav
independent control of WeChat's and Soda Music's internal audio levels.

AMS metadata still comes from the display's existing Apple Media Service client.
Its public track attributes provide artist, album, title and duration, but no
artwork. This release does not substitute a stale Apple Music cover or fetch a
lookalike from a new service. The display's music page uses a local record
illustration with actual available title, artist, playback state and progress.
Playback controls target the active player through AMS/HID; availability depends
on the player's advertised commands.

The AA22 cruise-map recovery, original app data boundary and AA13-compatible
wire map packets are preserved.

Validation includes a real unsigned device build, all Swift regressions, call
reducer/transport timing and navigation-speech queue tests, production UI
interaction tests and native screenshots. Simulator service adapters and host
firmware tests do not establish actual WeChat integration, Soda metadata, radio
reception, hardware button placement or background behavior on the user's phone.
