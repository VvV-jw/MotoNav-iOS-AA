# iOS AA22 Cruise Map Recovery

Version: 0.15.22 (22). App and share identifiers remain
`com.example.motonav` and `com.example.motonav.share`.

Cruise previously had no current-map refresh action. Finished cruise packets did
not enter the packet cache because the controller only supplied a cache node for
planned routes. An unacknowledged map could also hold a newer covering map behind
it after movement had made the old map obsolete.

This change:

- Keeps a compact cruise status and refresh action above every tab.
- Restarts current-map work and transfer without disconnecting Bluetooth or
  deleting route preparation. The retained display map stays available until a
  replacement is accepted.
- Replaces an obsolete unacknowledged map when its replacement covers the current
  viewport. Late receipts for the old transfer cannot confirm the new map.
- Stores cruise packets with the same quantized centre used to build them.
- Retries failed preparation from the existing heartbeat after 3, 6, 12, 24 and
  then 30 seconds, using only a position no older than 15 seconds. Provider service
  cooldowns remain authoritative.
- Allows complete GTA raw-cache geometry to build while network downloads are
  paused. A missing tile still obeys the network gate.
- Reserves at least 45 seconds of GTA preparation lead and requires 200 metres of
  useful cruise-centre progress before repeating an early update.

The existing uncommitted GTA POI28 compatibility work is retained in this source
snapshot. It has its own codec and Android-fixture regressions.

AA13's verified receiver accepts only POI classes 20 through 26. This release
therefore strips newer POI classes from the transmitted copy, preserving every
road and water feature and the original seven POI classes. Complete POI28 packets
remain in the cache; upgrading the symbol protocol is outside this cruise fix.

Validation includes the production MapFeeder worker, cache and BLE-queue replay,
GTA offline/cache/pause cases, the complete Swift suite, unsigned device build,
and native UI interaction and layout captures. UI captures replace service
boundaries and do not prove GPS, radio reception or iOS background execution.
No field cruise log identified the unique cause of the reported ride interruption;
an updated IPA still needs a real cruise check on the user's phone and display.
