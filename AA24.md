# iOS AA24 Notification Setup

Version: 0.15.24 (24). Base app and share-extension identifiers remain
`com.example.motonav` and `com.example.motonav.share`. Cover the original native
app with the same signing account. Never uninstall it to apply this update.

The device-settings page displays the round screen's ANCS capability and actual
subscription state. It offers a connection check and a local example-notification
test. The example button does not create a real system notification.

Accessory replies are `CAP,ANCS,1` and `ANC,0` or `ANC,1`. Zero means that the
accessory subscription is not ready; it does not prove that the user denied
notification permission. Reconnection clears the old status and probes again.
Unknown or malformed packets do not change the state.

Real notifications travel directly from iOS to the bonded accessory through
ANCS. MotoNav does not request access to another app's notification database,
upload notification content or log message text. The Bluetooth system-sharing
permission remains owned by iOS. The existing native MotoNav AA23 can keep its
navigation link while the new accessory is being set up; AA24 adds the setup
status and test controls.
